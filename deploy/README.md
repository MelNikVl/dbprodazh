# Домашний сервер: запуск и обслуживание

Приложение доступно по [192.168.0.15:8050](http://192.168.0.15:8050). Один контейнер `dashboard` раздаёт готовый интерфейс и разрешённые исходные Excel. Импорт, расчёты и экспорт выполняются в браузере; отдельной базы данных нет.

## Каталоги и параметры

```text
/home/nik/apps/dbprodazh/
├── app/     # исходный код из архива и локальный .env
└── data/    # исходные Excel; в контейнере /data, только чтение
```

Настройки находятся в `/home/nik/apps/dbprodazh/app/.env`:

```dotenv
BIND_ADDRESS=192.168.0.15
PUBLIC_ORIGIN=http://192.168.0.15:8050
CRM_SAMPLE_DIR=/home/nik/apps/dbprodazh/data
```

- `BIND_ADDRESS` — адрес сетевого интерфейса, на котором публикуется порт `8050`.
- `PUBLIC_ORIGIN` — точный адрес, которым пользуется браузер, включая порт.
- `CRM_SAMPLE_DIR` — путь к исходникам на сервере; допустим и путь `../data` относительно проекта Compose.

Без `.env` порт публикуется на `127.0.0.1`, каталог данных — `../data`. Контейнер работает от UID/GID `1000:1000` с файловой системой только для чтения. Исходники должны быть доступны этому пользователю на чтение, а каталог — на чтение и проход.

## Первый запуск

Нужны Docker Engine и Docker Compose v2+. Текущая установка содержит архив кода без `.git`. При новом развёртывании можно передать такой же архив или клонировать репозиторий:

```sh
ssh nik@192.168.0.15
mkdir -p ~/apps/dbprodazh/data
cd ~/apps/dbprodazh
git clone https://github.com/MelNikVl/dbprodazh.git app
cd app
cp deploy/.env.example .env
```

Скопируйте исходники в `data/` отдельно от кода. Сервер выдаёт только эти пять имён:

- `2024 год.xlsx`
- `2025 год.xlsx`
- `2026 год.xlsx`
- `план Август (4).xlsx`
- `план Сентябрь (6).xlsx`

Если файлы находятся на рабочем компьютере, их можно передать по SFTP или SCP. Исходники не добавляются в репозиторий и не включаются в Docker-образ. Отсутствие файлов допустимо: через интерфейс можно импортировать выгрузки в текущую страницу браузера.

Из каталога `app/`:

```sh
docker compose up -d --build --wait
docker compose ps
curl --fail http://192.168.0.15:8050/health
curl --fail http://192.168.0.15:8050/local-samples
```

`/health` проверяет доступность HTTP-сервера. `/local-samples` возвращает список разрешённых файлов и признак их доступности. Успешный ответ `/health` не подтверждает наличие Excel или правильность показателей; после запуска откройте приложение и проверьте раздел «Качество данных».

Развёртывание рассчитано на доверенную домашнюю сеть. Авторизация пользователей не реализована: любой пользователь с доступом к адресу приложения может получить разрешённые Excel-файлы.

## Обновление кода и исходников

Текущий сервер получает архив кода, поэтому обновление готовится в рабочей копии репозитория на компьютере. В архив входят только файлы зафиксированного коммита; незакоммиченные изменения туда не попадут.

В локальном репозитории:

```sh
git pull --ff-only
git archive --format=tar.gz --output=../dbprodazh-release.tar.gz HEAD
git rev-parse HEAD > ../dbprodazh-release.commit
scp ../dbprodazh-release.tar.gz ../dbprodazh-release.commit nik@192.168.0.15:/home/nik/apps/dbprodazh/
```

На сервере после резервного копирования:

```sh
ssh nik@192.168.0.15
cd ~/apps/dbprodazh/app
tar -xzf ../dbprodazh-release.tar.gz -C .
cp ../dbprodazh-release.commit REVISION
docker compose up -d --build --wait
docker compose ps
```

Локальный `.env` и соседний каталог `data/` в архив релиза не входят. Команда распаковки выше рассчитана на архив `git archive` без внешнего каталога. Для установки, созданной через `git clone`, вместо передачи архива допустим `git pull --ff-only` внутри `app/`, затем та же команда Compose.

Для обновления данных замените соответствующий файл в `data/`, сохранив его имя, затем перезагрузите страницу. Пересборка образа для замены Excel не требуется. Чтобы браузер не прочитал недокопированный файл, сначала передайте файл под временным именем в тот же каталог, затем переименуйте его в рабочее имя.

Ручной импорт в браузере сохраняется только до перезагрузки страницы. Постоянный общий набор исходников обновляется в серверном каталоге `data/`.

## Логи, перезапуск и остановка

```sh
cd ~/apps/dbprodazh/app
docker compose logs --tail=100 dashboard
docker compose logs --follow dashboard
docker compose restart dashboard
```

Чтобы остановить приложение:

```sh
docker compose down
```

Каталог `data/` при остановке сохраняется. Политика `unless-stopped` запускает контейнер после перезагрузки сервера, если он не был остановлен вручную. Размер файлов журналов ограничен настройками Compose.

Если браузер получает `403`, проверьте совпадение открытого адреса с `PUBLIC_ORIGIN`. Если исходники не загружаются, проверьте `/local-samples`, точные имена файлов, `CRM_SAMPLE_DIR` и права на каталог. Если приложение недоступно, начните с `docker compose ps` и журналов `dashboard`.

## Резервное копирование

Сохраняйте `data/`, локальный `app/.env` и идентификатор версии кода. Пример приватной резервной копии на сервере:

```sh
umask 077
mkdir -p ~/backups/dbprodazh
stamp=$(date +%Y%m%d-%H%M%S)
tar -czf "$HOME/backups/dbprodazh/$stamp.tar.gz" \
  -C "$HOME/apps/dbprodazh" data app/.env
if [ -f "$HOME/apps/dbprodazh/app/REVISION" ]; then
  cp "$HOME/apps/dbprodazh/app/REVISION" "$HOME/backups/dbprodazh/$stamp.commit"
fi
```

Для защиты от отказа самого сервера храните копию архива также на отдельном приватном носителе или другом сервере. Архив содержит коммерческие исходники и конфигурацию; он не предназначен для публикации в GitHub.

При восстановлении остановите приложение, восстановите `data/` и `.env` из выбранного архива, проверьте права на чтение для UID `1000`, затем выполните `docker compose up -d --build --wait` из каталога `app/`. Версия кода определяется сохранённым идентификатором коммита.

Настройки справочников и порогов находятся в `localStorage` браузера и в серверный архив не входят. Для переноса сохраните JSON правил и значения порогов из раздела «Настройки». Незавершённые ручные импорты в память страницы также не являются частью серверной копии.

## Проверки и запуск без Docker

Проверки из корня репозитория:

```sh
npm ci
npm test
node --test server/routes.check.mjs
npm run build
```

HTTP-сервер можно запустить напрямую после сборки:

```sh
HOST=0.0.0.0 PORT=8050 \
CRM_SAMPLE_DIR=/home/nik/apps/dbprodazh/data \
PUBLIC_ORIGIN=http://192.168.0.15:8050 \
node server/index.mjs
```

Перед таким запуском остановите контейнер, занимающий тот же порт. Версия Node.js в контейнере закреплена в [Dockerfile](../Dockerfile); для воспроизводимого запуска вне контейнера используйте ту же версию.

Приватная сверка с исходными Excel описана в [основном README](../README.md#проверки). Исходники и файл контрольных значений не включаются в образ и не публикуются вместе с кодом.
